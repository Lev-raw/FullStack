One data shape is used everywhere: { id, title, date, image, readMoreUrl }. Admin writes it. Storage keeps it. The public Pulse & Page section only reads and displays it.

1. How a visitor and an admin enter the CMS

Public path

  1. Open homepage /
  2. Navbar → PULSE & PAGE → VIEW POSTS, or jump to #pulse
  3. PulsePage calls fetchPulsePosts()
  4. Cards show image, date, title, READ MORE

Admin path

  1. Navbar → PULSE & PAGE → MANAGE POSTS
  2. Or type /admin/pulse
  3. PulseAdmin calls the same fetchPulsePosts()
  4. Admin can add, edit, or delete

3. Storage decision — where the post actually lives

The frontend never talks to MongoDB directly. Components only call pulseApi.js. That file chooses the live API first, then localStorage if the API cannot be reached.

File map

  • PulseAdmin.jsx — CMS list and actions
  • PulsePostForm.jsx — add/edit form and image preview
